## Residual risks

1. **Project 01**: Timestamp freshness and event idempotency do **not** form a comprehensive persistent HMAC signature replay cache. Failure-after-accept is simulated. The n8n exporter is a demonstration bridge; Header Auth must be configured by the operator and the workflow needs a live n8n test.
2. **Project 02**: Intake endpoint does not provide enterprise authentication; mock classification and manual time-saved assumptions cannot validate real ROI. Local-only exposure reduces, but does not eliminate, risk.
3. **Project 03**: Signature-free shared-key authentication is lab-only; no per-reviewer identity. Heuristic checks are narrow and model-reported confidence is not calibrated. A passing decision is not an LLM security guarantee.
4. **All projects**: No external CRM/Jira/Slack deployment, no pen test and no production incident response SLA. Docker Compose startup and live n8n workflow execution require verification on a machine with Docker.

## Verification instructions

From a cloned repository run:

```bash
cd 01-rest-api-integration-hub && pip install -r processor/requirements.txt pytest && python -m pytest -q
cd ../02-ai-workflow-automation-engine && pip install -r requirements.txt && python -m pytest -q
cd ../03-llm-quality-gate && pip install -r requirements.txt && python -m pytest -q
```

For each module: `cp .env.example .env && docker compose config -q`. Running `docker compose up -d --build` is a separate runtime verification and must not be inferred from syntax checks.
